# UOL API: doklady z účetního systému (zjištěno 2026-10-11)

Zdroj: https://api.uol.cz/openapi.yaml (UOL Accounting REST API 1.0.5). Auth: Basic (e-mail uživatele : API token), uživatel musí mít oprávnění „REST API“. Produkční server `https://{customerId}.ucetnictvi.uol.cz/api` (customerId = `mypixel`, produkce `https://mypixel.ucetnictvi.uol.cz/api`), demo `https://test.demo.uol.cz/api`. Limit 30 požadavků / 10 s. Klíč ve scratchpadu `.uol_basic`, do repa ne; do Vercelu jen přes konektor (sensitive).

Co API umí (to, co potřebujeme): `POST /v1/contacts` (kupující), `POST /v1/sales_invoices` (faktura; `status: confirmed` = vystavená, `external_id` = naše ID objednávky pro idempotenci, `variable_symbol`, `payment_method`, `send_by_email`), `GET /v1/sales_invoices/{id}` s `Accept: application/pdf` (PDF) nebo `text/isdoc`. Číslo dokladu přiděluje UOL (`public_id`). Potvrzenou fakturu nejde smazat ani upravit bez `repairs`.

**Rozhodnuto Ondřejem 2026-10-11 12:4x:** typ dokladu „Faktura - daňový doklad“ (jako účetní dosud: standardní, nulová sazba, středisko `sidlo`, účet `fio_801_czk`, konstantní symbol 308, položka `vyvoj_softwaru` „Digitální materiály“, `VS <naše>` v poznámce), doklad odesílá naše aplikace (vytváří se v UOL), **neoznačuje se jako zaplacený** (párování dělá účetní).

Implementace (`printopia/src/lib/uol.ts`, `fulfil.ts`, `deliverPaid` v cronu Fio i Stripe webhooku): po zaplacení kontakt (`external_id` = ID objednávky) + potvrzená faktura (`external_id` = ID objednávky, opakování fakturu jen najde), PDF jde přílohou doručovacího e-mailu místo vlastního dokladu, číslo faktury v objednávce (`invoiceNo`) a v upozornění firmě. Testovací objednávky (1 Kč přes *.vercel.app) fakturu nevystavují. Výpadek UOL doručení nezastaví: odejde starý doklad a firma dostane upozornění „vystavte ručně“; vystaví-li se faktura, ale nejde stáhnout PDF, upozornění říká, že faktura už existuje. Env `UOL_AUTH` (sensitive, production, nastaveno konektorem 2026-10-11), volitelně `UOL_API_URL`, `UOL_PRODUCT`, `UOL_BANK`, `UOL_DEPARTMENT`, `UOL_CONSTANT_SYMBOL`. Ověřeno: produkční ping a existence produktu/účtu/střediska (read-only), payload proti DEMO serveru (201, PDF), e2e s falešným UOL. První ostrá faktura vznikne při první skutečné platbě; po ní zkontrolovat v UOL a rotovat klíč.
